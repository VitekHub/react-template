# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

npm is the package manager (a `package-lock.json` is committed).

- `npm run dev` — Vite dev server
- `npm run build` — type-check (`tsc -b`) then production build
- `npm run preview` — serve the production build
- `npm run lint` — ESLint
- `npm run format` / `npm run format:check` — Prettier (write / verify)
- `npm run typecheck` — `tsc --noEmit` against both `tsconfig.app.json` and `tsconfig.node.json`
- `npm test` — Vitest in watch mode
- `npm run test:run` — Vitest once
- `npm run validate` — lint + format (writes files) + tests + typecheck

Run a single test file:

```bash
npm run test:run src/lib/utils.test.ts
```

Do **not** insert `--` before the path; it is passed to Vitest as a name/path filter and will run everything matching instead of just that file.

## Stack

React 19 + TypeScript (strict) on Vite, TanStack Router (file-based), TanStack Query, Zustand, Tailwind CSS v4, i18next/react-i18next, Sonner, Zod, lucide-react. Vitest + Testing Library for tests.

## Architecture

- `src/main.tsx` imports `@/i18n/config` for its side effect (i18next init), then renders `AppProviders`.
- `src/providers.tsx` composes `QueryClientProvider` (from `@/lib/query-client`) around `RouterProvider` (from `@/router`). The `QueryClient` is a module-level singleton with `staleTime: 5min`, `retry: 1`, `refetchOnWindowFocus: false`.
- `src/router.tsx` creates the router from the generated `src/routeTree.gen.ts` and registers it via the `Register` module augmentation.
- `src/routes/` is TanStack Router's file-based tree. `__root.tsx` renders `<Outlet />` plus the Sonner `<Toaster />`. `routeTree.gen.ts` is generated by `@tanstack/router-plugin` during dev/build — never edit it; it is excluded from ESLint and Prettier.
- `src/features/<feature>/ui/` holds page components (e.g. `features/home/ui/HomePage.tsx`). Route files stay thin and just wire a feature component to `createFileRoute`. Add a route by creating `src/routes/<path>.tsx`; the route tree regenerates automatically. Route files may export `Route` alongside a component (`react-refresh/only-export-components` is disabled there).
- `src/lib/` holds shared utilities (`query-client.ts`, `utils.ts` with the `cn()` clsx + tailwind-merge helper).
- `src/stores/` is the placeholder for Zustand stores (currently only `.gitkeep`).
- `src/test/` holds the Vitest setup and the test render helper.

Path alias `@/*` → `src/*` is defined in both `vite.config.ts` and `tsconfig.app.json`; use it for all internal imports.

## i18n

`src/i18n/config.ts` lazy-loads namespaces through `i18next-resources-to-backend` from `src/i18n/locales/<lng>/<namespace>.json`, so new locale files must follow that path layout. Supported languages are `en` (fallback) and `cs`; namespace `common` is the default. Language is detected from localStorage key `react-template-language`, then the browser. `i18nReady` is the init promise (tests await it before asserting translations).

## Testing

Vitest runs with `globals: true`, jsdom, and `src/test/setup.ts` (jest-dom matchers + RTL cleanup). Tests are colocated as `src/**/*.{test,spec}.{ts,tsx}`; the router plugin ignores `*.test.tsx` when generating routes.

Import `render`, `screen`, and `userEvent` from `@/test/utils` instead of `@testing-library/react` directly. That helper wraps components in a fresh `QueryClientProvider` (retry off) and a **separate** i18next instance with all JSON resources loaded eagerly in English (Suspense disabled) — it does not reuse the app's lazy `i18n` instance.
